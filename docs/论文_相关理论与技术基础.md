# 第2章 相关理论与技术基础

## 2.1 数据预处理技术

### 2.1.1 数据清洗

数据清洗是可视化系统的基础，主要包括以下步骤：

**异常值过滤**：
- 过滤速度≤0的无效GPS数据
- 过滤流量≤0的异常数据
- 限制拥堵等级在1-5范围内

**缺失值补全**：
- 采用线性插值法补全缺失的速度数据
- 对缺失的拥堵等级赋值为默认值2（缓行）

**数据归一化**：
- 拥堵指数 = (1 - 实际速度/自由流速度) × 100
- 将速度数据转换为0-100的拥堵指数

### 2.1.2 数据聚合

按路段ID和时段聚合数据：
- 计算每个路段每小时的平均流量
- 计算每个路段每小时的平均速度
- 统计每个路段的拥堵时长

本章节对应课程第3章"数据采集与清洗"知识点，实践了异常值检测、缺失值处理、数据归一化等核心技术。

## 2.2 可视化设计原则

### 2.2.1 视觉编码原则

**颜色编码一致性**：采用国标《城市道路交通管理评价指标体系》规定的颜色编码，确保不同用户对拥堵等级的认知一致。

**视觉注意力引导**：通过颜色对比度、图表位置等方式引导用户关注重要信息。

**信息密度平衡**：悬停弹窗仅展示核心信息（流量、速度、拥堵指数），避免信息过载。

### 2.2.2 交互设计原则

**多视图联动**：点击热点列表自动定位地图，切换视图模式，实现跨视图数据关联。

**交互反馈**：悬停时显示详细信息，操作后有明确的视觉反馈。

**容错性设计**：数据加载失败时显示友好提示，支持一键重试。

## 2.3 可视化库选型对比

### 2.3.1 主流可视化库对比

| 指标 | ECharts | D3.js | Leaflet |
|------|---------|-------|---------|
| 易用性 | 高 | 低 | 中 |
| 图表类型 | 丰富 | 灵活 | 地图专用 |
| 地图支持 | 内置geo组件 | 需要扩展 | 原生支持 |
| 开发效率 | 高 | 低 | 中 |
| 社区活跃度 | 高 | 高 | 中 |

### 2.3.2 选型决策

本系统采用**Leaflet + ECharts**的技术组合：

**Leaflet**负责：
- 底图渲染
- 地理空间数据加载
- 地图缩放平移

**ECharts**负责：
- 多图表联动
- 颜色编码
- 统计图表展示

**选型理由**：
1. Leaflet轻量且支持自定义地图图层，适合加载北京市核心城区的道路GeoJSON数据
2. ECharts内置了丰富的图表组件，能快速实现路段排行榜、时段趋势分析等功能，开发效率比纯D3.js提升约40%
3. 两者都有活跃的社区支持，文档完善，便于问题排查
